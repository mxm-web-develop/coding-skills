# v1.0.0 人工验收

在临时示例项目验证，避免改动正在交付的业务项目。可安装此仓库本地版本；不需要先发布到 GitHub。

| 操作 | 应看到的结果 |
| --- | --- |
| 安装后说“汇报下当前开发计划” | 一屏内理解目标、当前进度、待决定问题和下一步；不会新增计划或要求先审批 |
| 说“调研下 SQLite 方案，看看是否适合我们项目” | 基于项目约束说明适用性、成本、风险和来源；不会直接安装依赖或开始实现 |
| 说“添加个新功能，导出当前列表为 CSV” | 澄清确实缺失的需求，沿用已有约定，测试和评审后给出可操作的人工验证卡 |
| 按卡片验证并回复“不通过，导出字段顺序错了” | 原任务继续修复，新代码重新验证，不另开重复任务 |
| 按新卡片验证并明确回复“验证通过” | 当前能力与计划更新，任务完成，过程材料归档；查询历史仍能找到结果和测试 |
| 连续完成多个任务后查询计划 | 默认只展示当前有效计划和有限数量的进行中任务；旧计划和历史失败不抢占当前进度 |
| 在有进行中任务、待确认方案和未提交代码的 0.4.x 示例项目更新安装 | 先备份再转换；AI 提取旧要求并重新扫描；核对前暂停开发，核对后从同一任务继续，原代码和待确认事项保留 |
| 升级核对中途退出，再说“继续之前的计划” | 识别未完成升级，接着核对；不会把安装成功当成迁移完成 |

记录哪个操作符合预期，哪个有问题及实际表现。只有你明确验证通过，当前改造任务才会完成归档。发布可以单独延后。

自动回归覆盖安装/卸载、多 IDE 交接、旧记录迁移、代码变化使证据失效、验收拒绝、归档追溯、过期计划清理和常用语句分流。真实会话验收用于确认 AI 是否自然地执行这些约定；关键词分流测试本身不能保证所有模型在任意表达下都自动触发。
