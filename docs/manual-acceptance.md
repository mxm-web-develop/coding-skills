# v0.3.0 人工全流程验收

这份清单用于把 AI Flow 安装到真实项目后进行人工体验。重点不是检查内部文件名，而是观察用户是否始终知道：当前理解、正在做什么、哪些内容已经确认、是否修改代码、测试是否真实通过，以及下一步需要决定什么。

## 开始前

1. 在目标项目根目录安装所用 IDE 的版本。
2. Reload IDE Window，并开启新的 Agent 对话。
3. 如果同一仓库还会使用另一款 IDE，再运行对应安装参数；确认项目中没有出现第二套进度文档。

## 空白项目路径

发送：

```text
初始化这个空白项目。先和我确认第一个版本的目标、技术方向和界面体验，再开始开发。
```

应观察到：

- 先讨论用户、问题、首版范围、明确不做的内容和成功条件。
- 每次只询问一个真正会改变结果的问题。
- 技术选择说明候选方案的优势、弱点、项目影响和推荐理由。
- 界面方向不明确时提供可打开的 HTML 体验稿；用户确认前不写生产页面。
- 对话不要求用户理解 Skill、Work Item、Checkpoint、Evidence、状态码、对象编号或内部目录。

## 已有项目路径

发送：

```text
把这个已有项目接入流程。先告诉我当前版本、已有功能、测试情况和文档冲突，不要修改业务代码。
```

应观察到：

- 先只读检查代码、Git、版本、依赖、测试、部署和文档。
- 明确区分代码直接证明的事实、合理推断和需要用户确认的内容。
- 初始化只整理文档；疑似废弃代码和目录只做标记。
- 文档归档会逐条展示源位置和目标位置，得到明确批准前不会移动。
- 当前 README、许可证、运行手册、有效架构说明和工具引用资料默认受到保护。

## 中断与补充

在开发任务中依次尝试：

```text
先停一下，项目现在是什么版本？测试过没有？
```

```text
我补充一个条件：大额操作必须人工确认。
```

```text
顺便解释一下当前技术方案为什么这样选。
```

```text
继续上次的开发。
```

应观察到：

- 状态问题得到直接回答，原任务没有被取消、复制或自动推进。
- 补充条件影响到哪里会被说明；可保留的成果不会全部重做。
- 无关问题不会被当成新需求或待确认操作的批准。
- “继续”会先检查代码版本和最近保存的进度，不会越过仍在等待确认的技术、发布、删除或移动操作。

## 切换 IDE

在一个 IDE 中让任务停在可恢复位置，再安装并打开另一个 IDE，然后发送：

```text
继续这个项目上次中断的开发，先告诉我已经完成了什么和下一步是什么。
```

应观察到只有一套项目状态和看板；新 IDE 会核对当前代码是否与暂停时一致，然后从同一任务继续。如果代码已经变化，应先解释差异而不是强行恢复。

## 完成与发布

发送：

```text
所有测试都通过了吗？准备发布，但在真正推送、打标签或发布前先告诉我会做什么。
```

应观察到：

- “通过”来自实际命令、当前代码版本和未被修改的日志，不是 Agent 的文字判断。
- 目标、需求、技术选择、开发任务、测试、代码版本和发布内容可以完整追踪。
- 未完成任务、未确认技术选择、缺失测试、失败结果或断开的记录会阻止发布。
- 推送、合并、标签、GitHub Release、部署、删除和文件移动仍分别需要相应授权。
