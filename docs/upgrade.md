# 升级后继续原项目

升级分为工具更新与项目资料核对。工具安装成功不等于旧资料已经整理完毕。

1. 用原安装入口执行 update；源码安装可执行 `AI_FLOW_BUILD_SOURCE=1 ./install/install.sh update --target <项目路径> --source <新版源码路径>`。
2. 安装器先用新版工具检查、备份旧资料，生成逐文件转换清单，再更新已安装平台的 Skill 和工具。它保留业务代码、原任务身份、未完成计划、待确认事项和旧资料原件。
3. 对 AI 说“升级后继续之前的计划”。AI 读取备份和转换清单，把仍有效的需求、约束、验收条件、决定和未完成事项补回当前记录；重新扫描项目语言、组件和验证方式；修复旧资料链接。不兼容的记录保存在历史区，不再直接作为当前结论使用。
4. 校验通过后，给出“原先做到哪里、整理了什么、仍需决定什么、接着做什么”的短说明，恢复同一个任务。旧测试不会自动变成新版代码的测试证据。

安装器只整理 AI Flow 管理的资料。散落在业务目录的手写文档先做盘点，移动前仍需精确的来源/目标清单。升级也不会自动批准原来未确认的方案。

## 中断和恢复

升级状态与备份保存在 `.ai-flow/state/upgrade.json` 和 `.ai-flow/archive/upgrades/`。默认不要手工改动这两处。遇到冲突时，AI 应说明哪份内容发生变化，并保留两份内容供核对。

- 准备/转换中断：重跑 update，使用同一份清单继续；如果业务代码或旧记录已改变，先保留变化并重新核对，不能盲目覆盖。
- 核对中断：再次说“继续升级整理”，从未完成事项继续，不创建第二套计划。
- 尚未完成核对且需要退回：`flowctl project upgrade --mode restore --root <项目路径>` 恢复备份中的原资料；新产生的冲突内容保存在恢复备份目录。随后重新安装原版本工具。此命令只恢复记录，不会自动降级工具，也不回滚业务代码。
- 升级已完成且开始新开发：不能盲目恢复整份快照。按保存的逐文件清单比较并恢复必要内容，保留升级后的新工作。

维护者可用 `project upgrade --mode check|prepare|apply|finish|restore` 分段诊断。`finish` 必须有整理结论，并逐项声明已核对的旧资料；声明必须对应实际提取和校验，不能用批量确认代替阅读。
